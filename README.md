# Сервис управления подписками

## Технологии

- Java 21
- Spring Boot 3.4.4
- Onno Framework 2.0.0
- Spring Data JDBC
- H2 Database
- Maven Wrapper
- JUnit 5
- Mockito и AssertJ
- Lombok

## Структура проекта

```text
src/main/java/com/example/raujavatest
├── domain
│   ├── catalogs       # Клиенты и тарифы
│   ├── documents      # Платежи и подписки
│   ├── enumerations   # Статусы и способы оплаты
│   └── registers      # Балансы и выручка
├── jobs               # Фоновое обновление статусов
├── repositories       # Репозитории Spring Data
├── support            # Серверный расчёт строк и разрешение ссылок
└── ui
    ├── layouts        # Навигация приложения
    ├── pages          # Дашборд с основными показателями
    └── views          # Представления сущностей Onno
```

## Требования

Для запуска необходимы:

- JDK 21;
- доступ к Maven Central для первой загрузки зависимостей.

Отдельно устанавливать Maven не требуется — в проекте есть Maven Wrapper.

Проверить активную версию Java:

```bash
java -version
```

Если на macOS установлено несколько JDK, перед запуском можно выбрать Java 21:

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
export PATH="$JAVA_HOME/bin:$PATH"
```

## Запуск приложения

На macOS или Linux:

```bash
./mvnw spring-boot:run
```

На Windows:

```bat
mvnw.cmd spring-boot:run
```

После запуска интерфейс доступен по адресу:

```text
http://localhost:8080
```

## База данных

Приложение использует файловую базу H2:

```text
./data/subscriptions.mv.db
```

Схема создаётся и обновляется автоматически при запуске благодаря настройке:

```properties
onno.schema.mode=apply
```

Одновременно с одной файловой базой должен работать только один экземпляр приложения. Иначе H2 сообщит, что файл базы данных заблокирован.

## Запуск тестов

Чтобы тесты не конфликтовали с запущенным приложением и его файловой базой, используется отдельная база в памяти:

```bash
./mvnw clean test -Dspring.datasource.url=jdbc:h2:mem:rau_test
```

В проекте реализовано **16 автоматических тестов**. Они проверяют:

- проведение платежа;
- расчёт строк и общего итога подписки;
- расчёт даты окончания;
- доступность тарифов;
- обязательные поля и положительное число периодов;
- отсутствие движений у отменённой подписки;
- обновление статусов фоновой задачей;
- разрешение ссылок на тарифы;
- защиту серверной цены от подмены через запрос.

## Ручной проверочный сценарий

Ниже приведены 10 шагов для ручной проверки приложения через UI. Это не перечень автоматических тестов.

1. Создать клиента.
2. Создать доступный тариф стоимостью `500` с периодом `30` дней.
3. Создать платёж на `1000` для клиента, сохранить и провести его.
4. Проверить, что баланс клиента стал равен `1000`.
5. Создать подписку на один период выбранного тарифа.
6. Проверить автоматически рассчитанные сумму `500` и дату окончания.
7. Сохранить и провести подписку.
8. Проверить, что баланс уменьшился до `500`, а в выручке появился оборот `500`.
9. Попытаться провести подписку стоимостью больше остатка и убедиться, что проведение отклонено без частичных движений.
10. Провести отменённую подписку и убедиться, что баланс и выручка не изменились.
